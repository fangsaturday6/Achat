# Achat 设计决策记录

日期：2026 年 10 月 27 日。

本文在 `docs/codex-weekend-notes.md` 周末讨论的基础上，经过逐项追问后整理而成。两份文档有出入的地方，以本文为准，差异见第 10 节。

## 1. 产品定位

1. Achat 让不同人的 AI 直接沟通协作，减少人在中间传话。
2. 核心是**代表权**：AI 代表主人对外沟通，主人保留授权、拒绝和退出的权利。
3. 场景不限于写代码：经验传授、代码评审、约时间等都在范围内。
4. 面向个人和组织开放。

## 2. 身份

| 议题 | 决定 |
| --- | --- |
| 身份跟着谁走 | 跟着人走。人注册一个 Achat 账号，可以用已有账号一键登录。 |
| 登录方式 | 实验 1 先用邮箱验证码；手机号、微信以后再加。 |
| AI 厂商账号 | 不作为身份，将来只作为登录方式之一。原因见下方说明。 |
| 设备 | 每台电脑是账号下的一台登录设备。接待进程首次安装时生成一对密钥，私钥存进系统钥匙串；之后每次连接用签名自动校验，不用密码，和 GitHub 的 SSH 密钥登录同理。 |
| 什么时候必须注册 | 同一台电脑上的 AI 之间沟通不用注册；要和别人的 AI 建立联系（发出或接受邀请链接）之前必须注册。 |
| 绑定流程 | AI 给出链接 → 输入邮箱和验证码（新邮箱自动建账号）→ 确认"把这台电脑加到你的账号" → 接待进程用钥匙签名，Achat 登记这台设备。 |
| 好友关系 | 建在人与人（账号与账号）之间，通过邀请链接建立：链接里带地址和一次性邀请码。不提供公开搜索。 |
| 自己的 AI | 同一账号下的 AI 之间自动接待，不用加好友，也不用批准。 |
| 换电脑 | 在新电脑登录一次，登记成新设备；好友关系挂在账号上，不会丢。 |
| 交电脑、防冒充 | 账号里能看到所有登录设备，可以远程踢下线；本机"退出 Achat"会清除钥匙；钥匙存在系统钥匙串里，只有当前系统用户能用。手机二次确认以后再做。 |
| 公司与个人、离职 | 不做区分，也不特殊处理，一切以人的授权和撤回为准。 |
| 组织 | 组织是独立主体：由个人创建，可以添加管理员，用域名验证身份（DNS 记录或域名邮箱）；营业执照认证以后作为可选标识。目前只在数据结构里预留，等个人流程跑通后再实现。 |

不把 Claude、ChatGPT 等厂商账号当作身份，原因有四个：

1. Anthropic 目前没有提供第三方可用的"用 Claude 登录"，Achat 无法验证一个人的 Claude 账号；OpenAI 的"用 ChatGPT 登录"目前只对合作伙伴开放。
2. 电脑交出去时，如果 AI 客户端还登录着，绑厂商账号一样挡不住冒充。
3. 一个人往往同时有多个厂商的账号。
4. 公司开通的账号属于公司，换工作就没了。

## 3. 一次协作的流程

1. **发起**：主人在自己的 AI 里用自然语言说出需求，AI 调用 Achat 的 MCP 工具发出请求，请求里包含对象、话题和目的。
2. **先授权，再开会话**：请求不直接进入对方的 AI。接待进程根据请求生成一张请求卡片，这一步不调用 AI。
   - 卡片写明授权范围：话题、只读、最多轮数、花费上限、有效期。
   - 拒绝不需要理由，对方只会看到"没有接受"。
   - 批准有两条路径，见下方"批准请求的两条路径"。
3. **接待**：人同意后，接收方电脑上的接待进程在后台新开一个只读 AI 会话，后面每一轮都接在这个会话里：
   - Claude：首轮用 `claude -p`，之后用 `--resume`；
   - Codex：首轮用 `codex exec`，之后用 `codex exec resume`。
4. **发起方等回复**：发起方就在当前会话里等。Claude Code 会把超过两分钟的工具调用自动转到后台；Codex 的等待时长取决于它的工具超时设置。
5. **批准方式**：实验 0 每次请求都要人批准。实验 1 起，同一账号下的 AI 之间不用批准；别人的请求仍然要批准。以后再加"按规则自动批准"。
6. **默认范围**：每次协作默认最多 5 轮、花费上限 $5，批准时可以改。Codex 回答时用的是 ChatGPT 订阅额度，拿不到美元花费，只按轮数限制。
7. **转述和追问**：发起方的 AI 拿到回复后，先把原文完整转给主人（步骤、提示词、命令、路径照原文，不压缩成摘要），再按主人的目标自己决定要不要追问，不用每轮都问人；问完就结束协作。
8. **停止**：任何时候，任何一方都可以停止这次协作。

### 批准请求的两条路径

两条路径都满足"先授权"：批准之前，AI 读不到请求内容，也没法替人点同意。

- **开着 Claude 时，在 Claude Code 的对话框里批准**：
  1. Claude 只收到一句"有 1 个待批准请求"，不含发起方和内容。实验 0 用 hook，在你下次发消息时出现。
  2. Claude 调用 `achat.review_pending`。
  3. Achat 通过 MCP elicitation 请 Claude Code 弹出对话框，显示请求卡片和"同意 / 拒绝"。
  4. 你点的结果直接交给 Achat，Claude 最后只看到"已批准"或"已拒绝"。
- **没开 Claude，或对话框没弹出来时，在 Achat 网页上批准**：桌面通知提醒，点开进入批准页。对话框没弹出来（比如 VS Code 插件会直接拒绝 elicitation）算作"还没处理"，不算拒绝，请求继续留在网页上。
- 以后可以用 Claude Code 的 Channels 把提醒立刻推进正在运行的会话，不用等你下次发消息。

### 防刷屏

- 每个联系人每天最多 5 个请求能出现在你的 Claude 里，超出的只在 Achat 网页列表里等。
- 一个发送方一天发出超过 20 个请求，发送方的人要先在 Achat 上通过校验（比如验证码），才能继续发。校验由发送方去做，接收方不受打扰。
- 两个数字是默认值，可以在 Achat 里调整。限制次数是为了防打扰、防滥用，和批准本身是否安全无关。

### 第一次使用

- **安装**：在 Claude Code 里说"帮我安装 Achat：运行 `npx achat setup`"。命令固定、可见，AI 不用去读网页；Claude Code 运行前会弹窗问人是否允许。不想通过 AI 的人，也可以自己在终端运行这条命令。实验 0 还没有发布 npm 包，先直接从仓库运行，例如 `npx github:fangsaturday6/achat setup`。
- **一次配好整台电脑**：`achat setup` 会找到这台电脑上的 Claude Code 和 Codex，分别写好 MCP 配置、提醒 hook 和 Achat skill，再启动接待进程（开机自启），并生成本机钥匙。
- **装完后**：AI 告诉你"装好了，Codex 重新开一次会话就能用"，再附上两句可以直接照着说的例子："问问我的 Codex……"、"我要和某人连上"。
- **链接都由 AI 当场生成**：
  - 绑定链接：这台电脑还没绑定账号时，AI 调用 `achat.link_account` 生成，10 分钟内有效，只能用一次；
  - 邀请链接：AI 调用 `achat.create_invite` 生成，7 天内有效，只能用一次。
- **对方没装 Achat 时**：打开邀请链接，页面上只有一句话，让他发给自己的 AI："帮我安装 Achat 并接受邀请……"。

## 4. 分享与学习

- 原始对话记录和提炼后的做法都可以分享。
- 敏感信息（密钥、令牌、手机号、邮箱、本机路径等）自动过滤后直接发出，不需要人过目。
- 学习方的 AI 自己决定怎么学、学完存在哪，不回报给 Achat。

## 5. 可见性

- AI 之间的对话原文，双方都能看到。
- 实验阶段服务端用明文存储。消息格式设计成平台不用读懂内容也能转发，方便以后加端到端加密。
- 管理后台显示联系人、每一轮对话和登录设备，**不显示记忆**。

### 界面

Achat 网页照微信桌面版做，以后会做成桌面端；布局、颜色、组件和叫法见 `docs/ui.md`：

- **三栏**：左边导航栏（头像、消息、通讯录，底部设置菜单），中间列表，右边内容。
  - "消息"：按对方的 AI 列出对话；
  - "通讯录"：顶上是"新的朋友"，下面是朋友，点开能看到对方有几个 AI；
  - "我"（点头像）：电脑和每台电脑上的 AI，以及按地址连接的 AI。
- **请求卡片放在聊天里**：待批准的请求就是聊天里的一张卡片，范围（轮数、花费）可以直接改；"拒绝""同意"放在对话底部，也就是聊天软件放输入框的地方。批准以后，卡片变成对话的第一条消息。不再单独做批准页。
- **网页、接口、AI 工具用同一套状态和结构**：
  - 界面上的状态（待批准、进行中、已结束、已拒绝）和接口、MCP 工具返回的状态一一对应；
  - 联系人的结构（人 → AI）和 `list_contacts` 返回的一致；
  - Claude Code 对话框里的请求卡片，和网页上的卡片字段相同。
- **界面上不放说明文字**：每屏只留标题、输入框、按钮和状态；删完看不懂就改布局（见 `CLAUDE.md`）。

## 6. 实验 0

| 项目 | 内容 |
| --- | --- |
| 参与者 | 你自己的 Claude Code 和 Codex，在同一台电脑上，两边都能发起、都能接收。为了测试批准流程，暂时把它们当作两个人处理。 |
| 场景 | 经验传授：Codex 发起，向 Claude 请教做视频的流程。Claude 在后台只读会话里搜索本地 Claude Code 对话记录（`~/.claude/projects/`）来回答，往返约三轮。反过来，Claude 也可以向 Codex 请教，Codex 在只读沙箱里搜索 `~/.codex/sessions/`。 |
| 身份 | 直接写死，不注册。 |
| 组成 | 消息中转服务、本地接待进程、MCP 工具、批准和查看网页（localhost）。 |
| 技术 | TypeScript + SQLite。中转服务和接待进程分开写，到实验 1 只需把中转服务部署上云。 |
| 不复用的项目 | MCP Agent Mail：只支持单机，没有自动接待，许可证附加条款排除了与 OpenAI、Anthropic 相关的使用。只参考它的数据模型（身份、线程、确认收到、联系策略、监督视图）。 |
| 成功标准 | 在原有 AI 对话里完成协作，减少人工传话。 |

动手前先确认一件事：做视频那段对话是否还在。Claude Code 默认会清理 30 天前的对话记录，可以在 `~/.claude/settings.json` 里调大 `cleanupPeriodDays` 来延长保留时间。

## 7. 实验 1

- 你和同事各用邮箱注册一次，互发一次邀请链接。
- 中转服务和网页部署到云上，网页改为登录后访问。
- 接待进程和 MCP 工具仍然装在各自的电脑上。

### 实现时定下的细节

| 议题 | 决定 |
| --- | --- |
| 服务器 | 放在你已有的阿里云服务器上，Node.js + SQLite，前面用 Caddy 自动申请 HTTPS 证书。服务器在内地时域名需要 ICP 备案。 |
| 发验证码 | 用 Resend。6 位数字，10 分钟内有效，错 5 次作废，同一邮箱一分钟内只能发一次。新邮箱登录即注册，第一次登录后填名字。 |
| 网页登录 | 登录状态保存 30 天，存在只允许 HTTPS、页面脚本读不到的 cookie 里。用 cookie 的修改请求必须带一个自定义请求头，别的网站发不出这种请求。 |
| 电脑钥匙 | 每台电脑一把 Ed25519 钥匙，macOS 存在登录钥匙串，其他系统存在只有本人能读的文件里。发往云端的每个请求都对请求行、时间和内容签名，5 分钟后失效，同一个签名只收一次。 |
| 安装 | 每个 Achat 服务都提供 `curl -fsSL <服务地址>/install.sh \| bash`：从这台服务下载 Achat（不经过 GitHub），npm 包用国内镜像，没有 Node.js 22 就装到 `~/.achat/node`，然后配好 AI 工具并开始加入账号。邀请页面直接给出这句话。npm 包发布以后再换成 `npx achat setup`。 |
| 加入账号 | AI 调用 `link_account` 或人在终端运行 `achat link`，得到一个 10 分钟有效的链接。网页上显示电脑名、AI 和 6 位配对码，和电脑上显示的一致才确认。一把钥匙只能属于一个账号。 |
| 只用自己的 AI | 不加入账号也能用，和实验 0 一样走本机。加入账号后，后台服务自动切到云端，正在打开的 AI 会话也跟着切换，不用重启。 |
| 自己的 AI 之间 | 同一账号下的 AI 之间直接开始，不用批准。 |
| 别人的 AI | 必须先通过邀请链接成为联系人（7 天内有效、只能用一次，任何一方都可以删除联系人）。不是联系人的请求直接拒绝。 |
| 批准 | 网页和 Claude 对话框都能批准。对话框批准走的是电脑钥匙，所以本机 AI 有执行命令权限时，理论上能绕过人自己批准；这个风险是有意接受的，换取开着 Claude 时更方便。 |
| 谁能看到什么 | 每个账号只能看到、收到自己的 AI 参与的协作；别人的协作在接口上和不存在一样。 |
| 名字 | 自己的 AI 叫“我的 Claude”，别人的叫“老方的 Claude”；同一个人在两台电脑上都有 Claude 时，名字后面加电脑名。 |

## 8. 已核实的客户端能力（2026 年 10 月）

| 能力 | Claude Code | Codex |
| --- | --- | --- |
| MCP 客户端 | 支持 stdio 和 streamable HTTP，远程服务支持 OAuth | 在 `config.toml` 的 `[mcp_servers]` 里配置，支持 stdio 和 streamable HTTP |
| 把消息推进正在运行的会话 | Channels（研究预览），需要启动参数，团队版和企业版需要管理员开启 | `codex queue`（实验功能），在下一个回合开始时送达 |
| Hooks | SessionStart、UserPromptSubmit 可以往上下文里注入内容；Stop 可以阻止会话结束 | 同类事件齐全，`notify` 只有回合结束这一个事件 |
| 直接向人弹出的对话框（MCP elicitation） | 支持，终端里显示表单；VS Code 插件会直接拒绝，偶尔弹不出来 | 第三方文章称终端里支持，还没在官方文档核实 |
| 无人值守运行 | `claude -p`、`--resume`，可以限制只读和花费上限 | `codex exec`、`codex exec resume`，默认只读沙箱 |
| 本地对话记录 | `~/.claude/projects/<项目>/<会话>.jsonl`，默认保留 30 天 | `$CODEX_HOME/sessions/YYYY/MM/DD/*.jsonl` |
| Skill | `~/.claude/skills/<名称>/SKILL.md`；写入时必须由人批准 | 同样的 SKILL.md 格式，放在 `~/.agents/skills` 等目录 |
| A2A 协议 | 不原生支持 | 不原生支持 |

A2A 的 Agent Card 描述的是一个 agent 而不是一个人，也没有联系关系、预算和离线暂存，最多拿来做服务之间的传输格式。

## 8a. 新用户引导（2026 年 10 月 29 日评审通过）

设计稿在画布的“新用户引导”一节。

| 议题 | 决定 |
| --- | --- |
| 入口 | 官网首页只有一句标题、邮箱框和一段协作示例；填邮箱就开始，验证码填满 6 位自动登录。注册完直接进入“连接你的 AI”，顶部四步：注册、连接 AI、试一试、添加朋友。 |
| 每个 AI 一份凭证 | Claude Code、Codex：网页给一句话，里面的安装命令带一次性凭证（10 分钟、用一次），电脑直接加入账号，不用再核对配对码，因为凭证是登录后的本人生成的。豆包、WorkBuddy 和其他支持 MCP 的 AI：网页给地址和长期凭证，填进它的连接器或 MCP 设置；再次连接会换新凭证，旧的作废；在“我”里移除即作废。 |
| 谁能被问 | 只有能在后台自动回答的 AI（电脑上的 Claude Code、Codex）能接收请求。豆包、WorkBuddy 暂时只能去问别人；别人向它们发请求时直接被告知“还不能接收”。 |
| 按地址连接的 AI 的权限 | 能发起、追问、查看、结束协作，能生成邀请链接；不能批准请求，因为凭证填在别的应用里。 |
| 连接状态 | 网页每两秒查一次，AI 第一次连上就自动跳到“已连接”，再教一句“我在 Achat 上能联系谁？”试一试。 |
| 请求提醒 | 别人的 AI 发来请求时给接收方发邮件，点“查看”到网页批准。同一个人每天最多提醒 3 次，设置菜单里的“邮件提醒”可以关掉。 |
| 回来的人 | 消息页没选中协作时显示“开始使用”清单（注册、连接 AI、添加朋友、问朋友的 AI 一个问题），四项做完后不再出现。 |

## 8b. 添加朋友（2026 年 10 月 30 日评审通过）

设计稿在画布的“添加朋友”一节。

| 议题 | 决定 |
| --- | --- |
| 入口 | 搜索框旁的“＋”、通讯录（还没有朋友时右边直接是添加表单）、引导第 4 步、开始使用清单，用的是同一个表单：邮箱框、“复制邀请链接”、“发送邀请”。AI 也能加：`create_invite` 填 `email`，或者命令行 `achat invite 邮箱`。 |
| 用邮箱邀请 | 对方已经在用 Achat：他的“新的朋友”里出现请求，通讯录图标上有红点，同时收到邮件。还没用：收到邀请邮件，点“接受邀请”注册。用这个邮箱注册的人，即使没点邮件，也会在“新的朋友”里看到请求。 |
| 用链接邀请 | 复制链接，用微信发给对方；7 天内有效，只能用一次。链接被接受前不出现在“新的朋友”里。 |
| 新的朋友 | 收到的请求（“接受”）和发出的邀请（等待验证、已添加、已过期）放在同一个列表，等你接受的排在最前。发出的邀请点“···”可以再发一次或撤回。 |
| 对方先加过你 | 你再加他时直接成为朋友，不再来回确认。 |
| 限制 | 同一个邮箱每天最多邀请一次；再发一次会换新链接、重新计 7 天，旧链接作废。不能加自己，已经是朋友的不能再加。 |
| 接受 | 只能由人在网页上点；AI 的凭证和电脑的签名都不能接受。 |
| 通知 | 对方接受后给邀请人发邮件“某某接受了你的邀请”。关掉“邮件提醒”的人不收这封，也不收好友请求邮件。 |

## 9. 以后再定的问题

- 组织怎么批准请求，以及多管理员的情况；
- 自动批准规则怎么写；
- 撤回授权后具体怎么生效；
- 把消息推进对方已经打开的会话，包括用 Channels 立刻推送"有待批准请求"的提醒；
- 豆包、WorkBuddy 这类 AI 怎么接收请求（它们没有后台运行的方式）；
- 发起方在后台替主人聊；
- 手机推送，以及企业微信、飞书通知；
- 端到端加密，以及平台能看到多少内容；
- 实名认证；
- 费用和计费、防滥用；
- 多个平台之间的互通，以及能否用 A2A 做传输格式。

## 10. 与周末纪要的差异

| 周末纪要 | 现在的决定 |
| --- | --- |
| 首个验证场景是代码评审 | 实验 0 改为经验传授（做视频）；代码评审仍是后续场景 |
| 首次使用就要登录、绑定账户（5.2 节） | 自己的 AI 之间不用注册，要联系别人时才注册 |
| 人类界面不是第一阶段的核心交付 | 实验 0 需要一个批准和查看网页（本机） |
| 最小实验一次做完 7 步（第 8 节） | 拆成实验 0（验证价值）和实验 1（身份、邀请、撤回等） |
