## 计划 1、2 整体审查后留给计划 3、4 的问题（2026-11-18）

- 补答（`groups.ts` 的 `takeUp`）不看有没有更新的“正在看”，重连时可能多叫醒一次、多扣一次次数。
- 一次回答只把“正在看”的 @ 算答过（`settle`），被它覆盖的更早几条下面还挂着“不在线 / 额度用完了”。（计划 3 已修）
- 加轮弹框：发起方提前结束时不关；电脑睡着时进了最后一轮，醒来后 `recover()` 不会补弹。
- 解散不作废还开着的邀请（被邀请的人点了是 409）；解散后再退群或移出，还会往只读的群里写系统消息。（计划 3 已修）
- 被邀请的人看得到开场白带的附件却下载不了：要定给不给看。（计划 3 已修）
- `GroupService.checkFiles` 和 `RelayService.checkFiles` 是重复的一段；有几处报错带 id，网页做出来前要改成人话。（报错带 id 计划 3 已修；`checkFiles` 重复留给计划 4）
- 20 MB 上传测试在机器忙时偶尔 “fetch failed”，怀疑是服务端 5 秒关闲置连接、客户端复用旧连接。

开始之前：工作区里可能有别的会话没提交的改动。每个任务提交时只加本任务的文件，碰到别人也改过的文件用 `git add -p`。
